# UI and Accessibility

상태: 기준

## 레이아웃과 반응형

- 명확한 시각적 위계와 모듈형 카드 구조를 사용한다.
- 데스크톱과 모바일에서 모든 핵심 기능에 접근할 수 있어야 한다.
- 작은 화면에서는 상세 패널과 모달이 내용을 가리지 않고 스크롤 가능해야 한다.
- 터치 대상은 오작동을 줄일 수 있는 충분한 크기와 간격을 가진다.

## 테마

- 라이트 테마와 다크 테마를 전환할 수 있다.
- 텍스트, 입력, 포커스, 차트 및 그래프가 두 테마에서 충분한 대비를 유지한다.
- 색상만으로 선택, 오류, 관계 강도 또는 서비스 상태를 전달하지 않는다.

## 피드백

- 비동기 작업은 로딩, 성공, 오류 상태를 구분한다.
- 전환 효과는 작업 결과를 이해하도록 돕되 입력을 막지 않는다.
- 동작 감소 환경 설정을 존중한다.
- 서비스 상태와 로컬 데이터 보호 안내를 표시한다.

## 키보드와 포커스

- 모든 대화형 요소는 키보드로 접근하고 실행할 수 있다.
- 포커스 표시를 제거하지 않는다.
- 모달이 열리면 내부로 포커스를 이동하고 배경으로 빠져나가지 않게 한다.
- 모달이 닫히면 호출 요소로 포커스를 복귀한다.
- Escape 닫기를 지원하되 진행 중 데이터 손실이 있으면 확인 절차를 둔다.

## 이름과 상태

- 입력에는 시각적·프로그램적 레이블을 제공한다.
- 아이콘 단독 버튼에는 접근 가능한 이름을 제공한다.
- 오류 메시지는 관련 필드와 연결한다.
- 동적으로 변한 결과와 저장 상태는 필요한 경우 보조 기술에 알린다.

## 법적 안내

- 서비스 이용약관 및 개인정보처리방침을 모달로 열람할 수 있다.
- 모달은 키보드, 포커스 및 닫기 동작 요구사항을 따른다.
- 정책 내용은 기능 UI와 분리해 읽을 수 있는 구조로 제공한다.
