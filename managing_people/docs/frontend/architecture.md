# Frontend Architecture

상태: 기준

## 책임 영역

- 인증 세션과 현재 사용자 식별
- 사용자별 인재 및 네트워크 상태 관리
- 인재 탐색, 편집 및 시각화
- 네트워크 선택과 관리
- JSON·Markdown 입출력
- 자연어 분석 요청과 결과 검토
- 테마, 모달, 반응형 레이아웃 및 접근성

## 상태 경계

인증 상태와 사용자 데이터 상태를 분리한다. 사용자 데이터 상태는 현재 사용자의 안정적인 고유 식별자가 확정된 뒤 초기화한다.

필수 상태 전이:

1. 애플리케이션 시작 시 세션을 복원한다.
2. 인증되지 않은 경우 사용자별 데이터를 비운다.
3. 인증된 경우 해당 사용자의 네임스페이스만 불러온다.
4. 계정 전환 시 이전 데이터와 선택 상태를 제거한다.
5. 새 사용자의 데이터를 검증한 뒤 화면에 노출한다.

## 영속화

- 사용자별 네임스페이스를 사용한다.
- 직렬화 및 역직렬화 실패를 처리한다.
- 손상된 저장 데이터는 현재 상태에 부분 병합하지 않는다.
- 쓰기 실패 시 저장되었다고 표시하지 않고 복구 가능한 오류를 알린다.
- 저장 방식이 바뀌어도 [공용 데이터 모델](../shared/data-model.md)의 의미를 유지한다.

## 렌더링

- 목록, 상세 패널, 레이더 차트 및 네트워크 맵은 동일한 정규화 상태를 사용한다.
- 프로필 변경은 관련된 모든 표현에 즉시 반영한다.
- 큰 관계망에서도 입력에 반응하도록 애니메이션과 물리 계산 비용을 제한한다.

## 외부 경계

- 파일과 브라우저 저장소 입력은 파싱 후 검증한다.
- 서버 응답은 API 계약에 맞는지 확인한다.
- AI 분석 결과는 사용자 확인 전 임시 후보 상태에 둔다.
