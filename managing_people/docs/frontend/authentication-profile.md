# Authentication and Profile

상태: 기준

## 회원가입

- 이메일, 실명, 소속, 직책 및 비밀번호를 입력받는다.
- 이메일 형식과 중복을 검증한다.
- 비밀번호 강도를 측정해 이해 가능한 피드백으로 표시한다.
- 필드 오류는 해당 입력과 연결하고 입력값을 불필요하게 지우지 않는다.
- 가입 성공 후 세션 시작 여부를 일관된 정책으로 처리한다.

## 로그인과 로그아웃

- 등록된 계정 자격 증명을 검증한다.
- 실패 시 계정 존재 여부나 비밀번호 세부 정보를 과도하게 노출하지 않는다.
- 로그인 성공 후 해당 사용자의 데이터만 초기화한다.
- 로그아웃 시 현재 사용자 데이터, 선택 상태 및 민감한 메모리 값을 제거한다.
- 계정 전환 중 이전 사용자의 화면이 새 세션에 남지 않게 한다.

## 데모 계정

- 개발 또는 시연 환경에서만 제공할 수 있다.
- 일반 계정과 동일한 사용자 격리 규칙을 적용한다.
- 운영 환경 노출 여부는 명시적인 설정으로 통제한다.

## 프로필 수정

- 사용자는 자신의 실명, 소속, 직책 등 허용된 정보를 수정할 수 있다.
- 사용자 소유권의 기준인 고유 식별자는 변경하지 않는다.
- 이메일 변경이 인증에 영향을 주면 별도 검증 절차를 적용한다.
- 저장 성공과 실패를 명확히 알린다.

## 비밀번호 변경

- 프로필 일반 수정과 분리된 확인 절차를 사용한다.
- 현재 비밀번호 또는 동등한 재인증을 요구한다.
- 새 비밀번호 강도와 확인 값 일치를 검증한다.
- 비밀번호 원문을 로그, 내보내기 또는 일반 상태 저장소에 남기지 않는다.

## 주의

브라우저 기반 데모 인증은 운영 수준의 서버 인증과 동일한 보안을 제공하지 않는다. 실제 운영 인증 도입 시 사용자별 데이터 계약과 세션 전환 불변 조건을 유지해야 한다.
