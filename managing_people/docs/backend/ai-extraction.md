# AI Extraction

상태: 기준

## 목적

비정형 원문에서 확인 가능한 인물 정보와 관계를 추출하되, 사실과 해석을 구분하고 개인정보를 추측하지 않는다.

## 공급자 경계

- 공급자 SDK, 모델 및 인증 값은 서버 내부 구성으로 캡슐화한다.
- 모델 변경이 공용 API 및 데이터 모델 변경을 요구하지 않도록 변환 계층을 둔다.
- 원문과 기능 수행에 필요한 최소 지시만 전송한다.
- 공급자 응답과 사용량 정보에 민감한 값이 있는지 고려해 로그를 제한한다.

## 추출 지침

- 문서에 등장하는 실제 인물만 추출한다.
- 원문에 없는 연락처, 소속 및 관계를 생성하지 않는다.
- 사실 기반 이력은 원문 근거에 한정한다.
- 정성적 성향과 전략적 적합도는 해석임을 구분한다.
- 점수는 정의된 척도와 범위에 맞춘다.
- 관계는 결과에 포함된 인물 식별자를 참조한다.
- 중복 인물을 가능한 한 같은 인물로 정규화하되 근거가 부족하면 임의로 병합하지 않는다.

## 구조화 출력

가능하면 공급자의 구조화 출력 기능으로 스키마를 강제한다. 공급자가 이를 지원하지 않거나 보장이 충분하지 않으면 서버가 파싱 후 동일한 수준으로 검증한다.

검증 항목:

- 최상위 인재 배열
- 필수 식별자와 이름
- 식별자 유일성
- 네 가지 점수의 존재, 숫자 타입 및 범위
- 태그와 선택 필드 타입
- 연락처 형식
- 관계 강도와 대상 참조
- 허용 가능한 항목 수와 출력 크기

## 실패 처리

- 파싱 또는 검증 실패 결과는 부분적으로 반환하지 않는다.
- 일시적 공급자 장애의 재시도는 제한적이고 중복 요청 영향을 고려한다.
- 공급자 오류를 [공통 오류 계약](error-handling.md)으로 변환한다.
- 원문이나 실패 응답 전체를 일반 로그에 기록하지 않는다.
