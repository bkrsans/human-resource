# Backend Error Handling

상태: 기준

## 오류 응답 계약

모든 API 오류는 일관된 JSON 구조를 사용한다.

- `code`: 클라이언트 분기용 안정된 식별자
- `message`: 사용자에게 노출 가능한 안전한 설명
- `details`: 필요한 경우에만 제공하는 비민감 검증 정보

필드 이름은 구현에서 달라질 수 있지만 세 의미를 유지한다. 내부 예외 객체를 직렬화해 반환하지 않는다.

## 상태 분류

- 형식, 필수 값 또는 범위 오류는 클라이언트 입력 오류로 분류한다.
- 크기 제한 초과는 별도 오류로 분류한다.
- 지원하지 않는 API 경로와 메서드를 구분한다.
- AI 설정 누락은 서버 설정 오류로 분류한다.
- 공급자 시간 초과와 일시 장애는 재시도 가능한 외부 의존성 오류로 표현할 수 있다.
- 공급자 출력 불일치는 잘못된 게이트웨이 결과로 취급하며 클라이언트 데이터로 반환하지 않는다.
- 알 수 없는 예외는 일반 서버 오류로 변환한다.

## 로그

- 요청 상관 식별자를 사용해 사용자 응답과 서버 로그를 연결할 수 있다.
- 스택은 서버 내부 로그에만 남기며 운영 정책에 따라 접근을 제한한다.
- API 키, 비밀번호, 토큰, 전체 자연어 원문 및 전체 공급자 응답을 기록하지 않는다.
- 검증 실패는 민감하지 않은 필드 경로와 오류 종류만 기록한다.

## 복구

- 클라이언트가 재시도 가능한 오류와 수정이 필요한 입력 오류를 구분할 수 있게 한다.
- 재시도는 상한과 지연을 적용하고 무한 반복하지 않는다.
- 오류 후에도 서버가 다음 요청을 정상 처리할 수 있어야 한다.
- 외부 호출 실패는 클라이언트의 기존 데이터를 변경하지 않는다.
