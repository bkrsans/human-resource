# Import and Export Contract

상태: 기준

## 공통 원칙

- 가져오기와 복원은 기존 상태와 분리된 임시 데이터에서 완료까지 검증한다.
- 내보낸 데이터는 다시 가져왔을 때 의미상 동일한 프로필과 관계를 복원해야 한다.
- 알 수 없는 필드, 중복 식별자, 잘못된 점수 및 존재하지 않는 관계 대상의 처리 정책을 일관되게 적용한다.
- 민감한 인증 정보와 서버 비밀은 어떤 내보내기에도 포함하지 않는다.

## Markdown

Markdown 템플릿은 사람이 읽고 편집할 수 있는 표준 섹션으로 다음 정보를 표현한다.

- 인물 식별자와 이름
- 소속 및 연락처처럼 존재하는 프로필 정보
- 네 가지 역량 점수
- 전문 분야 태그
- 에너지 비용
- 사실, 해석 및 전략적 적합도
- 다른 인물과의 연결 관계

규칙:

- 필수 섹션과 선택 섹션을 구분한다.
- 선택 값이 없으면 빈 정보를 임의 생성하지 않는다.
- 구문 오류는 가능한 위치와 원인을 사용자에게 알린다.
- 인코딩과 줄바꿈 차이로 의미가 바뀌지 않아야 한다.
- 내보내기 후 재가져오기 왕복 테스트를 유지한다.

## JSON Backup

백업은 다음을 포함한다.

- 백업 형식 버전
- 사용자 데이터에 속한 네트워크 목록
- 각 네트워크의 인재와 관계
- 복원에 필요한 비민감 설정

복원 검증:

- 최상위 구조와 형식 버전
- 필수 필드와 타입
- 식별자 유일성
- 점수 및 관계 강도 범위
- 관계 대상 존재 여부
- 허용 가능한 입력 크기

복원은 사용자의 명시적 확인 후 수행한다. 실패 시 기존 데이터 전체를 유지한다.

## 호환성

형식 변경은 버전으로 구분한다. 지원하지 않는 미래 형식은 추측해 복원하지 않고 안전하게 거부한다. 이전 형식 변환이 필요하면 순수 변환과 검증을 거쳐 현재 모델로 만든 뒤 반영한다.
