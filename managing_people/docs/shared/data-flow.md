# Shared Data Flow

상태: 기준

## 세션과 사용자 데이터

1. 인증 계층이 현재 사용자의 고유 식별자를 확정한다.
2. 상태 계층이 해당 식별자의 네임스페이스에서만 데이터를 읽는다.
3. 읽은 데이터를 역직렬화하고 데이터 계약에 맞는지 검증한다.
4. 검증에 실패하면 손상된 값을 현재 상태로 사용하지 않고 안전한 오류 상태를 제공한다.
5. 모든 쓰기는 현재 사용자 식별자의 네임스페이스에만 수행한다.
6. 로그아웃 또는 계정 전환 시 이전 사용자의 메모리 상태를 제거한 후 새 데이터를 불러온다.

## 직접 편집

1. 사용자가 인재 또는 네트워크 변경을 시작한다.
2. UI가 입력을 검증한다.
3. 상태 계층이 참조 무결성과 현재 사용자 소유권을 확인한다.
4. 변경을 메모리와 영속 저장소에 일관되게 반영한다.
5. 시각화와 목록은 같은 상태를 구독해 즉시 갱신한다.

## 파일 가져오기와 복원

1. 사용자가 파일 또는 텍스트를 명시적으로 선택한다.
2. 입력을 임시 영역에서 파싱한다.
3. 전체 구조, 타입, 범위, 식별자 및 관계 참조를 검증한다.
4. 오류가 있으면 기존 상태를 유지하고 원인을 알린다.
5. 유효한 결과와 적용 영향을 사용자에게 확인시킨다.
6. 확인된 데이터만 현재 사용자 공간에 원자적으로 반영한다.

## 자연어 분석

1. 사용자가 원문 전송을 명시적으로 실행한다.
2. 클라이언트가 기본 형식과 크기를 확인하고 서버에 전송한다.
3. 서버가 요청을 재검증하고 필요한 최소 데이터만 AI 공급자에 보낸다.
4. 서버가 AI 출력을 공용 데이터 계약으로 검증한다.
5. 클라이언트가 구조화된 결과를 임시 후보로 표시한다.
6. 사용자가 결과를 검토하고 반영을 승인한다.
7. 승인된 데이터만 현재 사용자 공간에 저장한다.

## 실패 불변 조건

- 검증되지 않은 입력은 기존 데이터를 덮어쓰지 않는다.
- 실패한 계정 전환이 이전 사용자의 데이터를 새 사용자 화면에 남기지 않는다.
- 서버 또는 AI 오류가 비밀 값이나 원문 전체를 불필요하게 노출하지 않는다.
- 일부 항목만 유효한 입력의 부분 반영 여부는 기능 명세에 명확히 정의하며 기본값은 전체 거부다.
