# Security and Data Protection

상태: 기준

## 사용자 데이터 격리

- 모든 인재와 네트워크 접근은 현재 사용자의 고유 식별자를 기준으로 범위를 제한한다.
- 저장소 키를 구성할 때 사용자별 네임스페이스를 사용한다.
- 계정 전환 시 이전 사용자 상태, 선택 항목 및 캐시를 제거한다.
- 표시용 이메일, 이름 또는 사용자가 수정 가능한 필드를 소유권 키로 사용하지 않는다.
- 가져오기 데이터가 다른 사용자 네임스페이스나 계정 정보를 지정하도록 허용하지 않는다.

## 비밀 관리

- AI API 키와 그 밖의 자격 증명은 서버 환경 또는 승인된 비밀 저장소에서만 읽는다.
- 클라이언트 코드, 정적 자산, 파일 내보내기, API 응답 및 로그에 비밀을 포함하지 않는다.
- 오류 객체나 외부 공급자 응답을 그대로 클라이언트에 전달하지 않는다.
- 비밀이 누락된 경우 기능을 안전하게 중단하고 비민감한 설정 오류를 반환한다.

## 입력 경계

- 브라우저 저장소, 업로드 파일, 붙여넣은 Markdown, API 요청 및 AI 응답을 신뢰하지 않는다.
- 타입, 길이, 개수, 숫자 범위, 식별자 및 참조 무결성을 검증한다.
- 파일 및 자연어 입력에 합리적인 크기 제한을 적용한다.
- 화면에 표시하는 외부 텍스트는 실행 가능한 마크업이나 스크립트로 취급하지 않는다.

## 개인정보

- 자연어 분석은 사용자가 명시적으로 실행할 때만 원문을 서버로 전송한다.
- 외부 AI 서비스에는 분석에 필요한 최소 원문과 지시만 전송한다.
- 원문에서 확인되지 않은 연락처, 관계 또는 민감 정보를 추측하지 않는다.
- 사실 기반 이력과 모델의 해석을 구분해 사용자에게 표시한다.
- 백업 및 내보내기 전에 포함될 개인정보의 범위를 사용자가 이해할 수 있게 안내한다.

## 로깅과 오류

- 로그에는 비밀번호, API 키, 인증 토큰 및 불필요한 원문을 기록하지 않는다.
- 클라이언트 오류에는 안정된 코드와 안전한 메시지만 포함한다.
- 내부 스택, 파일 경로 및 공급자 자격 증명은 서버 경계 밖으로 노출하지 않는다.

## 변경 검토

인증, 저장소, 가져오기, 내보내기 또는 외부 AI 전송이 바뀌는 변경은 다음을 검토한다.

- 사용자 소유권 검증 위치
- 실패 시 기존 데이터 보존 여부
- 새로 저장·전송·기록되는 개인정보
- 클라이언트 번들 또는 응답의 비밀 노출 가능성
- 계정 전환 및 다중 계정 테스트
