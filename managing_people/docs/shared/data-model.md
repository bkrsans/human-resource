# Shared Data Model

상태: 기준

이 문서는 UI 상태, 파일 입출력 및 API 결과가 공유하는 의미 계약을 정의한다. 실제 속성명과 저장 형식은 구현 언어에 맞게 정할 수 있지만 의미와 검증 규칙은 일치해야 한다.

## User

필수 데이터:

- 변경되지 않는 사용자 고유 식별자
- 로그인에 사용하는 정규화된 이메일
- 실명
- 소속
- 직책
- 인증 검증에 필요한 정보

규칙:

- 이메일은 계정 식별 정책에 따라 중복을 방지한다.
- 비밀번호 원문을 일반 애플리케이션 데이터와 함께 저장하거나 내보내지 않는다.
- 사용자별 데이터의 소유권은 표시 이름이나 이메일이 아닌 고유 식별자로 판정한다.

## Person

필수 데이터:

- 네트워크 범위에서 유일하고 안정적인 식별자
- 이름
- 네 가지 역량 점수
- 전문 분야 태그 목록

선택 데이터:

- 소속
- 이메일과 전화번호
- 에너지 비용
- 사실 기반 이력
- 정성적 성향 해석
- 전략적 적합도
- 그 밖의 출처가 확인된 프로필 정보

규칙:

- 역량 점수는 애플리케이션이 정한 동일한 유한 범위 안의 숫자여야 한다.
- 태그는 빈 값을 제거하고 중복 비교 정책을 일관되게 적용한다.
- 연락처는 값이 있을 때 형식을 검증하며 추측해서 채우지 않는다.
- 사실, 해석 및 전략적 평가를 서로 다른 의미로 보존한다.

## Competency Stats

모든 인재는 다음 축을 동일한 척도로 가진다.

- 실행력
- 분석 및 연구력
- 창업가 성향
- 글로벌 역량

축을 추가하거나 의미·범위를 변경할 때는 시각화, Markdown, JSON, AI 스키마 및 테스트를 함께 갱신한다.

## Connection

필수 데이터:

- 출발 인물 식별자
- 도착 인물 식별자
- 관계 강도 또는 시너지 값

선택 데이터:

- 관계 유형
- 출처 또는 설명

규칙:

- 양 끝점은 같은 네트워크 안에 존재해야 한다.
- 자기 자신을 향하는 관계와 중복 관계의 허용 정책은 구현에서 하나로 통일한다.
- 강도 값은 정해진 유한 범위 안에 있어야 한다.
- 방향성이 없다면 끝점 순서가 달라도 같은 관계로 취급한다.

## Network

필수 데이터:

- 사용자 범위에서 유일한 식별자
- 이름
- 인재 목록
- 연결 관계 목록

선택 데이터:

- 설명 또는 프로젝트·부서 메타데이터
- 사용자 조정 노드 위치 및 화면 상태
- 생성 및 수정 시각

규칙:

- 네트워크는 정확히 한 사용자의 데이터 공간에 속한다.
- 복제 시 새 네트워크 식별자를 발급하고 내부 참조 무결성을 유지한다.
- 삭제 시 다른 네트워크나 사용자 데이터에 영향을 주지 않는다.

## Backup Envelope

JSON 백업에는 최소한 형식 버전과 네트워크 데이터가 포함되어야 한다. 계정 자격 증명과 서버 비밀은 포함하지 않는다. 형식 변경 시 이전 백업 지원 여부를 명시적으로 결정하고 검증 경로를 제공한다.
